# Готовность Бота К Пилоту На 5 Пользователей

Дата обновления: 11 июня 2026 года.

## Итог

Проект функционально и по ожидаемой нагрузке подходит для контролируемого пилота на пять человек. Локально реализованы основные механизмы защиты данных и восстановления. На VPS изменения в рамках этой подготовки не передавались и не запускались.

Автоматический набор содержит 169 тестов на момент обновления документа. Перед пилотом число нужно сверить с итоговым выводом `pytest`.

## Выполнено

- [x] Границы массовых заявок хранятся в `data_end_row`; регистрация не читает строки следующей пачки.
- [x] Создание массовой заявки блокируется по листу, регистрация по `batch_id`.
- [x] Массовая регистрация использует состояния `DRAFT`, `REGISTERING`, `REGISTERED`, поддерживает stale recovery и повторное подтверждение без дублей.
- [x] Одиночная отправка защищена блокировкой по `application_id`.
- [x] Маршрут одиночной заявки фиксируется перед первой попыткой и не меняется при повторе после дедлайна раскатки.
- [x] Перед append бот ищет `application_id` в целевом листе и восстанавливает SQLite tracking, если строка уже существует.
- [x] Tracking, состояние `SENT` и завершение черновика сохраняются одной транзакцией `BEGIN IMMEDIATE`.
- [x] Временные ошибки Google API повторяются с exponential backoff и jitter; `403` и ошибки схемы не повторяются.
- [x] После сетевой ошибки production Google client пересоздается.
- [x] SQLite использует WAL, `busy_timeout=10000`, `foreign_keys=ON`, `synchronous=NORMAL` и индексы рабочих выборок.
- [x] Добавлен backup через SQLite Backup API, retention семь дней, `integrity_check` и проверяемое восстановление.
- [x] Добавлены Compose backup service и примеры systemd timer на 03:00 Europe/Moscow.
- [x] Heartbeat обновляется только после успешного полного status polling.
- [x] Docker healthcheck отклоняет просроченный heartbeat и проверяет SQLite.
- [x] Завершенные массовые заявки исключаются из частого polling.
- [x] Ошибка Telegram одного пользователя не блокирует обработку остальных и не обновляет его tracking.
- [x] В Compose включена ротация логов: пять файлов по 10 МБ.
- [x] Подготовлен production Compose с фиксированным SHA-тегом и понятным rollback через предыдущий `APP_VERSION`.

## Фактические Ограничения Пилота

- Допускается только один экземпляр бота. Межпроцессная распределенная блокировка не реализована.
- Google Sheets остается внешним сервисом с квотами. Retry уменьшает влияние кратковременных сбоев, но не отменяет длительную недоступность или неверные права service account.
- Dashboard является производным представлением. Источник правды — рабочие таблицы направлений.
- Старые Google-листы автоматически не мигрируются в новые схемы.
- Backup подготовлен локально, но ежедневный timer и внешний каталог хранения еще должны быть настроены администратором на VPS.
- Нет отдельного alerting администратора. Неисправность видна через `unhealthy` и логи, поэтому во время пилота нужен ежедневный контроль.
- Rollback на старый image допустим только после проверки совместимости его кода с текущей схемой SQLite.
- Локальный `deploy.tar.gz` не должен использоваться: он может содержать секреты. Перед пилотом токены следует ротировать, если архив покидал доверенную машину.

## Рекомендуемый VPS

Минимум для пяти пользователей: 1 vCPU, 1 ГБ RAM, 15 ГБ SSD и 1 ГБ swap.

Рекомендуется: 1-2 vCPU, 2 ГБ RAM, 20 ГБ SSD. Docker image лучше собирать вне VPS, чтобы сборка не конкурировала с работающим ботом.

## Проверки Перед Запуском

1. Выполнить `pytest` и `python -m compileall src tests`.
2. Выполнить `docker compose config` и config production Compose с заданным `APP_VERSION`.
3. Собрать image с commit SHA и запустить контейнер локально.
4. Запустить контейнерные тесты.
5. Создать backup, проверить `integrity_check`, восстановить его в отдельный файл и проверить основные таблицы.
6. Проверить, что свежий heartbeat дает healthy, а просроченный — unhealthy.
7. Проверить двойную отправку одной заявки и двойное подтверждение массовой заявки.
8. Проверить две массовые заявки на одном листе: первая не должна читать или менять вторую.
9. Проверить уведомления двум пользователям, когда Telegram-отправка одному завершается ошибкой.
10. Зафиксировать текущий и предыдущий SHA image для rollback.

## Эксплуатация Пилота

- Ежедневно проверять `docker compose ps`, последние ошибки логов, свободное место и наличие свежего backup.
- Не использовать `docker compose down -v`.
- Перед каждым обновлением создавать backup.
- Не запускать второй экземпляр контейнера параллельно.
- При `unhealthy` сначала проверить heartbeat, Google API и SQLite, затем перезапускать контейнер.

## Критерий Готовности

Пилот можно запускать после успешного локального regression/smoke набора, настройки ежедневного backup на VPS и проверки rollback на предыдущий SHA image. Для пяти пользователей ожидаемым ограничителем является Google Sheets API, а не CPU или SQLite.
