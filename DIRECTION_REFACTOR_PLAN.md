# План Переделки Проекта Под Таблицы Направлений, Дашборд, Массовые Заявки И Уведомления

## Summary

Главное изменение: текущая система с одной Google-таблицей и листами `Высокий`, `Низкий`, `Массовые` заменяется на модель с рабочими таблицами направлений и отдельным read-only дашбордом.

Источник правды: **Google-таблицы направлений**.

Единый список заявок: **информационный дашборд**, который бот синхронизирует автоматически и в котором не предполагается ручное изменение статусов, комментариев или итоговых ответов.

## Текущая Модель Проекта

Сейчас проект реализует:

- Telegram-бот на `aiogram 3` с polling.
- SQLite-хранение черновиков, пользовательских дефолтов, отправленных заявок и массовых заявок.
- Одиночную заявку с пошаговым сбором данных.
- GigaChat-проверку поля `Суть изменений` для одиночной заявки.
- Google Sheets-запись одиночных заявок в листы:
  - `Высокий`;
  - `Низкий`.
- Массовую загрузку через отдельный лист `Массовые`.
- Уведомления по изменению статусов через polling Google Sheets.
- Сохранение жирного и зачеркнутого форматирования поля `Исходный текст` для одиночных заявок.
- ID заявки длиной 8 символов.
- Статусы и dropdown/цвета статусов в Google Sheets.

Эта модель больше не соответствует новым требованиям, потому что заявки теперь должны распределяться не по приоритету, а по направлениям, недельным вкладкам, интеграционным вкладкам и массовым пачкам.

## Целевая Продуктовая Модель

### Направления

Сценарист выбирает направление заявки:

- `ФЛ`;
- `SME`;
- `АИ`;
- `VoiceBot`;
- `Collection`.

Выбор направления должен быть гибридным:

- у пользователя может быть дефолтное направление;
- при создании заявки пользователь может использовать дефолт;
- при необходимости пользователь может выбрать другое направление вручную.

### Типы ответов

Для направлений `ФЛ`, `SME`, `АИ` пользователь выбирает тип ответа:

- `Раскатка`;
- `Срочные`;
- `Интеграция`.

Для `VoiceBot` и `Collection` тип ответа не выбирается.

### Интеграционные заявки

Интеграционные заявки идут **только** во вкладку `Интеграционные`.

Они не дублируются в недельные вкладки.

### Недельные вкладки

Для обычных заявок бот выбирает недельную вкладку.

Имя недельной вкладки: дата начала недели в формате `дд.мм`.

Пример: если заявка создана 5 июня, а понедельник недели - 1 июня, имя вкладки будет `01.06`.

Боту разрешено создавать вкладки внутри уже созданных Google-таблиц.

### Таблицы направлений

Google-таблицы направлений создаются только администратором.

Бот не создает новые Google-таблицы, но создает и форматирует вкладки внутри них.

Таблицы:

- отдельная таблица для `ФЛ`;
- отдельная таблица для `SME`;
- отдельная таблица для `АИ`;
- одна общая таблица для `VoiceBot` и `Collection`, но разные вкладки для этих направлений.

Для общей таблицы `VoiceBot`/`Collection` использовать префиксы вкладок:

- `VoiceBot 01.06`;
- `Collection 01.06`;
- `VoiceBot Интеграционные`, если интеграции для VoiceBot будут включены позже;
- `Collection Интеграционные`, если интеграции для Collection будут включены позже.

### Единый список заявок

Единый список заявок - отдельная Google-таблица-дашборд.

Он нужен для просмотра общего состояния всех заявок.

В дашборде не предполагается ручное изменение:

- статуса;
- комментариев редактора;
- итогового ответа;
- служебных данных.

Бот синхронизирует дашборд из таблиц направлений.

### Срочные ответы

Вопрос про срочные ответы остается для обсуждения позже.

На текущем этапе нужно заложить только технический признак:

- колонка `Срочная`;
- булевое значение `Да` / `Нет`;
- визуальное выделение срочных строк в таблицах и дашборде.

Бизнес-правила маршрутизации срочных заявок пока не реализовывать.

### Фильтры ADD / EDIT / CHIP

Пока не реализовывать как обязательную часть сценария.

Зафиксировать гипотезу:

- `ADD` - добавить новый ответ;
- `EDIT` - изменить существующий ответ;
- `CHIP` - изменить или добавить чип/кнопку/быстрый вариант ответа.

Пометить как вопрос для руководителя:

- кто выбирает значение;
- обязательно ли оно;
- влияет ли оно на маршрутизацию;
- нужно ли оно для всех направлений.

На текущем этапе можно подготовить необязательную колонку `Тип изменения`, но не строить на ней критичную логику.

## Новая Схема Рабочих Таблиц Направлений

Для недельных и интеграционных вкладок использовать единую схему:

1. `ID заявки`
2. `ID пачки`
3. `Тип заявки`
4. `Дата заявки`
5. `Направление`
6. `Тип ответа`
7. `Срочная`
8. `Автор заявки`
9. `Telegram ID`
10. `Статус`
11. `Интент`
12. `Закрепленный сценарист`
13. `Причина изменений`
14. `Суть изменений`
15. `Исходная суть изменений`
16. `Исходный текст`
17. `Вопросы/комментарии редактора`
18. `Ответ сценариста`
19. `Итоговый ответ редактора`
20. `LLM статус`
21. `LLM оценка`
22. `Тип изменения`

`ID пачки` пустой для одиночных заявок.

`Тип заявки`:

- `Одиночная`;
- `Массовая`.

`Статус` должен иметь dropdown и цветовое оформление.

`Тип изменения` пока необязателен и может быть пустым.

## Статусы

### Статусы одиночных заявок

Использовать статусы:

- `Новая`;
- `В работе`;
- `Нужны пояснения`;
- `Итоговый ответ готов`;
- `Принята`;
- `Отклонена`;
- `Отложена`.

### Статусы массовых заявок

Использовать статусы пачек:

- `Новая пачка`;
- `В работе`;
- `Нужны пояснения`;
- `Частично готова`;
- `Готова`;
- `Отклонена`;
- `Отложена`.

### Уведомляемые статусы

Для одиночных заявок уведомлять автора при переходе в:

- `Нужны пояснения`;
- `Итоговый ответ готов`;
- `Принята`;
- `Отклонена`;
- `Отложена`.

Для массовых заявок уведомлять автора при переходе в:

- `В работе`;
- `Нужны пояснения`;
- `Готова`;
- `Отклонена`;
- `Отложена`.

Не отправлять отдельное уведомление по каждой строке массовой заявки.

## Новая Схема Дашборда

Дашборд должен содержать компактные обзорные поля:

1. `ID заявки`
2. `ID пачки`
3. `Дата заявки`
4. `Направление`
5. `Тип заявки`
6. `Тип ответа`
7. `Срочная`
8. `Автор заявки`
9. `Статус`
10. `Итоговый ответ есть`
11. `Ссылка на рабочую строку`

Для массовых заявок можно добавлять агрегирующие строки по пачке или отдельный лист `Пачки`.

Рекомендуемая модель:

- лист `Заявки` - все одиночные заявки и строки массовых заявок;
- лист `Пачки` - агрегированные статусы массовых заявок.

Дашборд обновляется ботом.

Если пользователь вручную меняет дашборд, бот не обязан сохранять эти изменения.

## Изменения В UX Бота

### Главное меню

Кнопки первого уровня:

- `Одиночная заявка`;
- `Массовая заявка`;
- `Дефолты`.

### Дефолты

Меню дефолтов должно позволять задать, изменить и очистить:

- дефолтное направление;
- дефолтный интент;
- дефолтного сценариста.

### Одиночная заявка

Новый flow:

1. Выбор направления.
2. Выбор типа ответа, если направление `ФЛ`, `SME`, `АИ`.
3. Интент.
4. Закрепленный сценарист.
5. Причина изменений.
6. Суть изменений.
7. Исходный текст.
8. Признак срочности.
9. Финальная проверка.
10. Отправка.

Для `Интеграция` заявка попадает во вкладку `Интеграционные`.

Для остальных типов заявка попадает в недельную вкладку.

GigaChat остается только для одиночных заявок и только для поля `Суть изменений`.

### Массовая заявка

Новый flow:

1. Пользователь выбирает `Массовая заявка`.
2. Выбирает направление.
3. Бот создает секцию пачки в таблице выбранного направления.
4. Бот отправляет ссылку на место вставки.
5. Пользователь вручную вставляет строки в Google Sheets.
6. Фоновый polling регистрирует заполненные строки, присваивает ID заявок и связывает их с ID пачки.

Для массовой заявки GigaChat не вызывается.

Массовая заявка должна иметь один `ID пачки`, одно направление и много строк.

Тип ответа может меняться внутри строк пачки.

## Массовая Пачка В Таблице

В таблице направления бот создает секцию пачки:

- строка-шапка пачки;
- строка заголовков;
- резерв строк для вставки.

В шапке пачки:

- `ID пачки`;
- автор;
- Telegram ID;
- направление;
- дата создания;
- статус пачки;
- ссылка/служебная отметка.

Пользователь вставляет пользовательские данные в разрешенные колонки.

Бот при регистрации строк заполняет:

- `ID заявки`;
- `ID пачки`;
- `Тип заявки = Массовая`;
- `Дата заявки`;
- `Направление`;
- `Автор заявки`;
- `Telegram ID`;
- `Статус = Новая`.

## Google Sheets Сервисы

Заменить текущую логику `GoogleSheetsSubmissionService`, которая выбирает лист по приоритету, на routing-service:

- определить направление;
- определить целевую таблицу;
- определить вкладку:
  - `Интеграционные`, если тип ответа `Интеграция`;
  - недельная вкладка `дд.мм`, если обычная заявка;
  - вкладка с префиксом направления для общей таблицы VoiceBot/Collection.
- создать вкладку, если ее нет;
- проверить или создать заголовки;
- применить dropdown статусов, conditional formatting, ширины колонок, freeze header;
- добавить строку через `appendCells`.

Для `Исходный текст` сохранить rich text форматирование bold/strikethrough для одиночной заявки.

## Дашборд-Синхронизация

Добавить отдельный сервис синхронизации дашборда.

После создания заявки или регистрации массовой строки бот должен создать/обновить строку в дашборде.

Также polling должен обновлять дашборд при изменении:

- статуса;
- итогового ответа;
- рабочей ссылки;
- направления;
- признака срочности.

Дашборд должен искать строки по `ID заявки`, а не по номеру строки.

Если строки в дашборде нет, бот создает ее.

Если строка есть, бот обновляет ее.

## Уведомления

Polling должен читать рабочие таблицы направлений, а не дашборд.

Причина: источник правды - таблицы направлений.

Отслеживать по `ID заявки`.

Для каждой заявки хранить:

- последний известный статус;
- последний известный комментарий редактора;
- последний известный итоговый ответ;
- последнюю найденную строку;
- sheet/spreadsheet/sheet_id.

### Уведомления По Одиночным Заявкам

Формат:

```text
Изменились статусы заявок

A1B2C3D4: Новая -> Принята
```

ID заявки должен быть ссылкой на рабочую строку.

Link preview отключить.

Если заполнен итоговый ответ редактора, отправить отдельный блок:

```text
Итоговый ответ по заявке A1B2C3D4

[свернутый или сокращенный текст]
```

Если Telegram expandable blockquote поддерживается текущей версией Bot API/aiogram, использовать его.

Fallback: первые 700-1000 символов итогового ответа + ссылка на строку.

### Уведомления По Массовым Пачкам

Не уведомлять по каждой строке.

Группировать по `ID пачки`.

Формат:

```text
Изменения по массовой заявке BATCH-A1B2C3D4

Статус пачки: Новая пачка -> Готова
Готовых итоговых ответов: 12
Нужны пояснения: 2

Открыть пачку
```

Если пришли итоговые ответы по нескольким строкам пачки, отправлять digest.

Ограничение digest:

- максимум 10 итоговых ответов в одном сообщении;
- если больше 10, показать первые 10 и ссылку на пачку.

## Работа С Итоговым Ответом Редактора

Добавить колонку `Итоговый ответ редактора`.

Если значение появилось впервые или изменилось, бот уведомляет автора.

Для одиночной заявки:

- отправить итоговый ответ по заявке.

Для массовой заявки:

- собрать изменения по пачке;
- отправить digest;
- не отправлять отдельные сообщения на каждую строку.

Итоговый ответ должен быть HTML-экранирован перед отправкой в Telegram.

## ADD / EDIT / CHIP

На текущем этапе не делать обязательной частью flow.

Подготовить колонку `Тип изменения`, но не требовать заполнения.

В документации указать, что значения являются гипотезой и требуют подтверждения:

- `ADD` - добавление нового ответа;
- `EDIT` - изменение существующего;
- `CHIP` - изменение чипа/кнопки/быстрого варианта.

## Срочные Ответы

Добавить поле `Срочная`.

Для одиночной заявки добавить выбор:

- `Да`;

Для массовой заявки в шаблоне добавить колонку `Срочная`.

Визуальное оформление:

- срочные строки выделять цветом;
- в дашборде тоже показывать признак `Срочная`.

Не добавлять отдельную маршрутизацию срочных заявок до следующего обсуждения.

## Миграция

Автоматически мигрировать старые Google Sheets `Высокий`, `Низкий`, `Массовые` в новую модель не нужно.

Причина: новая модель меняет не только колонки, но и распределение по направлениям.

Старые данные оставить в старой таблице.

Для SQLite:

- добавить новые колонки через `ALTER TABLE`;
- существующие активные черновики без направления считать устаревшими;
- при продолжении старого черновика бот должен попросить выбрать направление и дальше продолжить сценарий.

Для уже отправленных старых заявок:

- оставить отслеживание старой модели отключаемым;
- после перехода на новую модель отслеживать только новые заявки в таблицах направлений.

## Assumptions

- Google-таблицы направлений создает администратор вручную.
- Бот имеет право создавать вкладки внутри таблиц направлений.
- Недельная вкладка называется датой понедельника текущей недели в формате `дд.мм`.
- Интеграционные заявки идут только во вкладку `Интеграционные`.
- Единый список заявок является read-only дашбордом.
- Источник правды для статусов и итоговых ответов - таблицы направлений.
- Срочные ответы пока требуют отдельного обсуждения; на текущем этапе реализуется только булевый признак и визуальное выделение.
- ADD/EDIT/CHIP пока считаются гипотезой и не становятся обязательной частью сценария.
- Старые Google Sheets-данные автоматически не мигрируются.
- Старые черновики в SQLite можно продолжить после дозаполнения новых обязательных полей.
- Для массовых заявок уведомления агрегируются по пачке, а не отправляются по каждой строке.

## Addendum: Срочные Заявки, Дашборд И Упрощенная Массовая Вставка

После дополнительного обсуждения зафиксированы уточнения:

- Срочность выбирается один раз.
- Для `ФЛ`, `SME`, `АИ` срочность определяется типом ответа: `Срочные` -> `Срочная = Да`, `Раскатка` и `Интеграция` -> `Срочная = Нет`.
- Для `VoiceBot` и `Collection` остается отдельный выбор `Обычная` / `Срочная`, потому что тип ответа для этих направлений не выбирается.
- Срочные заявки записываются только во вкладку `Срочные` выбранного направления и не дублируются в недельную вкладку.
- Для общей таблицы `VoiceBot` / `Collection` используются вкладки `VoiceBot Срочные` и `Collection Срочные`.
- Интеграционные заявки записываются только во вкладку `Интеграционные`; если у старых данных одновременно есть `Интеграция` и `Срочная = Да`, приоритет у интеграционной вкладки.
- В дашборде используется только лист `Заявки`.
- Массовая заявка отображается в дашборде одной агрегированной строкой по `ID пачки`; строки внутри нее в дашборд не добавляются.
- Колонка `Итоговый ответ есть` принимает только `Да` / `Нет` и означает наличие итогового ответа редактора: для одиночной заявки в рабочей строке, для пачки хотя бы в одной строке пачки.
- Массовая вставка упрощается до staging-листа `Массовый ввод`.
- Пользователь заполняет только диапазон `A:G`: `Тип ответа`, `Интент`, `Закрепленный сценарист`, `Причина изменений`, `Суть изменений`, `Исходный текст`, `Тип изменения`.
- Служебные и рабочие колонки справа используются в этом же листе: `H` - `ID заявки`, `I` - `Статус`, `J` - `Вопросы/комментарии редактора`, `K` - `Ответ/комментарий сценариста`, `L` - `Итоговый ответ редактора`.
- При создании пачки бот подсвечивает строки для вставки; после регистрации строки бот снимает подсветку.
- Строки массовой заявки маршрутизируются по `Тип ответа`: `Срочные` -> `Срочные`, `Интеграция` -> `Интеграционные`, остальные -> недельная вкладка.
