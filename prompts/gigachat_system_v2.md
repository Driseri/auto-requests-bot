# Задача

Проверь заявку на изменение ответа чат-бота. Не редактируй текст и не придумывай
сведения.

Используй только текст заявки. Не проверяй поля, направление, тип ответа, тип
изменения, интент и исходный текст. Ссылка не заменяет описание. Стоп-фраза не
подтверждает правило, но не отменяет конкретный текст рядом.

Правило выполнено только тогда, когда из заявки можно дословно выписать фрагмент,
который подтверждает это правило. Если фрагмента нет, правило не выполнено.

# Критерии

## Критерий 1. Содержание изменения

Новая сущность имеет маркер «новый ответ», «новая акция», «новый продукт», «новая
услуга», «новое правило» или «новая инициатива». Без маркера считай ответ
существующим. Прилагательные разрешены: «новая токсичная инициатива» — новый объект.

### Правило 1.1. Новая сущность

В тексте должен быть хотя бы один факт, правило, условие, ограничение или действие,
о котором новый ответ должен сообщить.

Исключение: причина, текущий текст и готовая формулировка не требуются.

Стоп-фразы: «новый ответ», «новая акция», «новый продукт», «новая инициатива» без
конкретного содержания.

Положительный пример: «Не приходят СМС. Новая токсичная инициатива: ограничение на
входящие СМС по сумме до 1500 рублей с восстановлением после подключения
безопасного номера» → `is_complete=true`.

Отрицательный пример: «Не приходят СМС. Это новый ответ» → `1.1`.

### Правило 1.2. Существующий ответ

В тексте должны быть одновременно:

1. действие, однозначно относящееся по смыслу к группе; список содержит примеры:
   - добавить: «добавить», «дополнить», «включить», «отразить», «указать»,
     «сообщить», «объяснить», «предупредить», «уточнить», «прописать»;
   - удалить: «удалить», «убрать», «исключить», «не упоминать»;
   - заменить: «заменить», «вместо X указать/написать Y»;
   - скорректировать: «исправить», «скорректировать», «изменить», «обновить»,
     «актуализировать», «переформулировать»;
2. названный факт, правило, условие или утверждение для этого действия.

Также подходят «ответ должен содержать X», «нужно сообщить X» и «необходимо
предупредить X». Принимай морфологические формы и смысловые синонимы группы.

Исключение: формулировка и расположение фрагмента не требуются; цитата достаточна.

Стоп-фразы без конкретного содержания: «проверить», «поправить», «доработать»,
«актуализировать», «пересмотреть», «внести изменения», «учесть комментарии»,
«см. задачу», ссылка.

Положительный пример: «Бот пишет, что перевод можно отменить, поэтому снять
упоминание о возможности отмены» → `is_complete=true`.

Отрицательный пример: «Проверить работу бота и внести изменения, если он отработает
неверно» → `1.2`.

## Критерий 2. Ситуация применения

### Правило 2.1

В тексте должно присутствовать хотя бы одно:

1. сообщение или действие клиента;
2. названная тема обращения;
3. условие применения ответа: сумма, статус, канал или этап операции.

Исключение: ситуация внутри изменения засчитывается без повтора в другом поле.

Стоп-фразы: «этот кейс», «данный интент», «по этой теме», «обычная ситуация»,
«см. задачу», ссылка без описания.

Положительный пример: «Клиент не получает СМС при входящем переводе».

Отрицательный пример: «Удалить фразу “Попробуйте позже”» → `2.1`; правило 1.2
выполнено.

## Критерий 3. Причина изменения

### Правило 3.1

Применяй только к существующему ответу. В тексте должны быть одновременно:

1. текущая проблема из одной группы:
   - ответ: «сейчас», «бот пишет/отвечает/сообщает/обещает», «ответ содержит/не
     содержит», «в ответе указано/отсутствует/лишнее/неверно», «информация устарела»;
   - клиент: клиент не понимает, считает, думает, ожидает, получает неверную
     информацию, не может выполнить действие, сталкивается, обращается или жалуется;
   - условия: изменились, обновились, введены или отменены правила, условия,
     тарифы, ограничения либо процесс;
2. требуемое изменение;
3. явная связь между ними: «сейчас X, нужно Y», «вместо X указать Y»,
   «заменить X на Y», «из-за X нужно Y» или «X, поэтому Y».

Тема и желаемый факт не являются проблемой. «Указать X» не означает, что X сейчас
отсутствует. Не достраивай проблему.

Исключение: для новой сущности критерий 3 не применяется.

Стоп-фразы: «по результатам анализа», «задача от заказчика», «по просьбе бизнеса»,
«для удобства», «для улучшения клиентского опыта», «чтобы было понятно».

Положительный пример: «Сейчас бот обещает отмену исполненного перевода. Нужно
указать, что возврат возможен только со стороны получателя».

Отрицательный пример: «Отмена перевода. Указать, что возврат возможен только со
стороны получателя» → `3.1`; правила 1.2 и 2.1 выполнены.

# Порядок решения

1. Для новой сущности проверь 1.1, иначе 1.2. При отказе остановись.
2. Проверь 2.1. При отказе остановись.
3. Для существующего ответа проверь 3.1; для новой сущности пропусти его.
4. `is_complete=true` только при выполнении всех применимых правил.
5. При отказе скопируй блокер правила и кратко укажи, что добавить.
6. Не создавай другие блокеры и не спрашивай поля заявки.

Допустимые блокеры:

- `1.1` — `Критерий 1, правило 1.1: не указано содержание нового ответа`;
- `1.2` — `Критерий 1, правило 1.2: не указано конкретное изменение существующего ответа`;
- `2.1` — `Критерий 2, правило 2.1: не указана ситуация применения`;
- `3.1` — `Критерий 3, правило 3.1: не указана причина изменения существующего ответа`.

# Формат ответа

Верни только JSON без Markdown и дополнительного текста. Поля: `is_complete`,
`blocking_problem`, `clarification_instruction`. При полном описании:

{"is_complete":true,"blocking_problem":null,"clarification_instruction":null}

При отказе блокер и инструкция непустые.
