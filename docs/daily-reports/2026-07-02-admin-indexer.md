# 02.07.2026 — Админская индексация ручных строк

## Что сделано

- Реализован редкий административный CLI `python -m app.sheet_indexer` для строк, которые были внесены или перенесены вручную в Google Sheets и не имеют `ID заявки` и технических полей.
- Инструмент работает в `dry-run` по умолчанию: сначала показывает безопасных кандидатов и отдельно строки, которые пропущены из-за неполного заполнения или непустых технических полей.
- Реальное выполнение требует `--execute` и явного списка `--rows`, чтобы не индексировать лишние строки массово.
- Для production-режима добавлена защита по пользователю: при записи нужно указать `--telegram-user-id` или явно выбрать ограниченный режим `--allow-unknown-user`.
- При индексации инструмент:
  - генерирует `ID заявки`;
  - заполняет технические поля в Google Sheets;
  - создаёт tracking в `submitted_applications`;
  - ставит projection в `dashboard_outbox`;
  - не вызывает GigaChat и не создаёт черновик пользователя.
- В `DraftRepository` добавлен атомарный метод `index_submitted_application()`, который сохраняет tracking и dashboard projection одной SQLite-транзакцией.
- Добавлены unit-тесты на поиск кандидатов ADD/EDIT и CHIPS, пропуск уже индексированных строк и фиксацию частично заполненных строк как `skipped`.
- Обновлены `README.md` и `docs/PILOT_OPERATIONS_GUIDE.md` с командами dry-run и execute.

## На что обратить внимание в эксплуатации

- Инструмент не должен запускаться автоматически и не должен заменять обычный workflow бота.
- Перед `--execute` нужно сначала смотреть `dry-run` и выполнять запись только по конкретным проверенным строкам.
- Если строка частично заполнена, её нельзя индексировать до ручной проверки.
- Если `telegram_user_id` неизвестен и используется `--allow-unknown-user`, личные уведомления по такой заявке не будут корректно доставляться сценаристу.
- Инструмент не переносит строки, не меняет пользовательские поля и не пытается восстанавливать черновики.
