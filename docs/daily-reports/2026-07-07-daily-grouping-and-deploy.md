## Баг дневной группировки

Проблема: в листе `Срочные` автоматически созданная группа за `02.07.26` визуально захватила строку с датой `07.07.26` и строку заявки после нее.

Проверены листы production Google Sheets read-only:

- FL / `Срочные`;
- FL / `Интеграции`.

Текущее состояние FL / `Срочные` на момент проверки:

- строка 29: `02.07.26`;
- группа под `02.07.26` сейчас охватывает строки 30-33;
- строка 34: `07.07.26`, сейчас не входит в группу `02.07.26`;
- строка 35: заявка `2BC4E591`, находится в отдельной группе 35-35;
- лист `Интеграции`: есть строка `02.07.26`, row groups отсутствуют.

## Вероятная причина

Корень проблемы найден в логике вставки строк через Google Sheets API.

При создании нового дневного блока код использовал:

`inheritFromBefore=True`

Это опасно, когда новая дата вставляется сразу после уже сгруппированных строк предыдущего дня. Google Sheets может унаследовать свойства предыдущей строки, включая принадлежность к row group. В результате новая дата и первая строка нового дня могут визуально оказаться внутри группы предыдущего дня.

Правильная логика:

- при создании нового дневного разделителя не наследовать свойства предыдущей строки;
- при добавлении заявки внутрь уже существующего дневного блока оставить старое поведение, чтобы форматирование внутри дня сохранялось.

## Риски

После выкладки фикса новые дневные блоки создаются с `inheritFromBefore=False`, поэтому новая строка даты не должна наследовать принадлежность к row group предыдущего дня. Для вставки в уже существующий дневной блок сохраняется `inheritFromBefore=True`, чтобы продолжать наследовать форматирование внутри дня.

Отдельно нужно учитывать, что текущие уже созданные Google row groups не исправляются кодом автоматически. Если в таблице уже есть лишняя группа, ее нужно поправить вручную или отдельным безопасным maintenance-скриптом.
