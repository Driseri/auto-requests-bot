# Alfa Auto Requests Bot

Telegram-бот для сбора заявок на изменение сценариев и ответов чат-ботов. Бот помогает сценаристам быстро заводить одиночные заявки и массовые заявки, отправляет данные в рабочие Google-таблицы направлений, синхронизирует read-only дашборд и уведомляет автора о важных изменениях статуса и итоговых ответах редактора.

## Что Реализовано

- Telegram-бот на `aiogram 3` с polling.
- Одиночные заявки с выбором направления, типа ответа, GigaChat-проверкой сути изменений и финальной проверкой перед отправкой.
- Массовые заявки: бот создает место в таблице направления, пользователь вставляет строки вручную и подтверждает заполнение кнопкой в Telegram.
- Google Sheets routing по направлениям: `ФЛ`, `SME`, `АИ`, `VoiceBot`, `Collection`.
- Для заявок `Раскатка` обязателен тип изменения `ADD`, `EDIT` или `CHIPS`. Недельные вкладки разделены на окна среды и четверга, а новые вкладки содержат отдельные вертикальные секции для каждого типа.
- Отдельная вкладка `Интеграционные` для интеграционных заявок.
- Read-only дашборд с компактным списком заявок и ссылками на рабочие строки.
- Уведомления по важным статусам и появлению итогового ответа редактора.
- SQLite-хранение черновиков, дефолтов пользователя, отправленных заявок и массовых заявок.
- Пользовательские дефолты для направления, интента и сценариста.
- ID заявки длиной 8 символов.
- Rich text перенос жирного и зачеркнутого Telegram-форматирования для поля `Исходный текст` в одиночных заявках.

## Актуальная Логика Срочности, Дашборда И Массовой Вставки

Срочность выбирается один раз. Для направлений `ФЛ`, `SME`, `АИ` она определяется типом ответа: `Срочные` означает `Срочная = Да`, `Раскатка` и `Интеграция` означают `Срочная = Нет`. Для `VoiceBot` и `Collection` тип ответа не выбирается, поэтому бот отдельно спрашивает `Обычная` / `Срочная`.

Срочные заявки не дублируются в недельные вкладки. Они записываются только во вкладку `Срочные`; для общей таблицы `VoiceBot` / `Collection` используются вкладки `VoiceBot Срочные` и `Collection Срочные`. Интеграционные заявки имеют приоритет маршрутизации и записываются только во вкладку `Интеграционные`.

Дашборд использует один лист `Заявки`: одиночные заявки отображаются отдельными строками, массовые заявки отображаются одной агрегированной строкой по `ID пачки`. Отдельные строки внутри массовой заявки в дашборд не добавляются. Колонка `Итоговый ответ есть` содержит только `Да` или `Нет`: для одиночной заявки это наличие текста в поле `Итоговый ответ редактора`, для массовой заявки - наличие хотя бы одного итогового ответа внутри нее.

Массовая вставка работает только в листе `Массовый ввод`. Пользователь заполняет компактный диапазон `A:G`: `Тип ответа`, `Интент`, `Закрепленный сценарист`, `Причина изменений`, `Суть изменений`, `Исходный текст`, `Тип изменения`. Тип изменения обязателен в каждой заполненной строке: `ADD`, `EDIT` или `CHIPS`. При ошибке хотя бы в одной строке бот не регистрирует массовую заявку частично. После успешной проверки бот заполняет `H:J` (`ID заявки`, `Статус`, `Редактор`), оставляет редакторские поля `K:M` и группирует строки.

## Конфигурация

Создайте `.env` по примеру `.env.example`.

```env
TELEGRAM_BOT_TOKEN=123456:telegram-token
TELEGRAM_PROXY_URL=
TELEGRAM_REQUEST_TIMEOUT=60
SQLITE_PATH=/data/app.db
BOT_TIMEZONE=Europe/Moscow
ROLLOUT_WEDNESDAY_CUTOFF=14:00
ROLLOUT_THURSDAY_CUTOFF=14:00
APPLICATION_EDITORS=редактор 1,редактор 2

GOOGLE_CREDENTIALS_PATH=/run/secrets/google_credentials.json
GOOGLE_DASHBOARD_SPREADSHEET_ID=dashboard-spreadsheet-id
GOOGLE_FL_SPREADSHEET_ID=fl-spreadsheet-id
GOOGLE_SME_SPREADSHEET_ID=sme-spreadsheet-id
GOOGLE_AI_SPREADSHEET_ID=ai-spreadsheet-id
GOOGLE_VOICE_COLLECTION_SPREADSHEET_ID=voice-collection-spreadsheet-id

GIGACHAT_CREDENTIALS=gigachat-authorization-key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat
GIGACHAT_VERIFY_SSL_CERTS=true

STATUS_POLLING_ENABLED=true
STATUS_POLLING_INTERVAL_SECONDS=30
DASHBOARD_SYNC_INTERVAL_SECONDS=300
```

Google-таблицы направлений и дашборд создаются администратором вручную. Боту нужны права редактора в этих таблицах через service account из `credentials.json`. Сам бот не создает новые spreadsheet-файлы, но создает вкладки внутри уже созданных таблиц.

Старые переменные `GOOGLE_SPREADSHEET_ID`, `GOOGLE_HIGH_PRIORITY_SHEET_NAME`, `GOOGLE_LOW_PRIORITY_SHEET_NAME`, `GOOGLE_BULK_SHEET_NAME` оставлены только для временной совместимости `.env`; новая логика маршрутизации их не использует.

## Направления И Вкладки

Пользователь выбирает направление:

- `ФЛ`
- `SME`
- `АИ`
- `VoiceBot`
- `Collection`

Для `ФЛ`, `SME`, `АИ` дополнительно выбирается тип ответа:

- `Раскатка`
- `Срочные`
- `Интеграция`

Для `VoiceBot` и `Collection` тип ответа не выбирается.

Заявки типа `Раскатка` распределяются по времени фактической отправки:

- до среды 14:00 по Москве - в лист среды текущей недели, например `01.06 ср`;
- со среды 14:00 включительно до четверга 14:00 - в лист четверга текущей недели, например `01.06 чт`;
- с четверга 14:00 включительно - в лист среды следующей недели, например `08.06 ср`.

Дата в имени - понедельник соответствующей недели. Часовой пояс и оба дедлайна настраиваются через `BOT_TIMEZONE`, `ROLLOUT_WEDNESDAY_CUTOFF` и `ROLLOUT_THURSDAY_CUTOFF`. Дата создания черновика на маршрутизацию не влияет.

Интеграционные заявки попадают только во вкладку `Интеграционные` и не дублируются в недельную вкладку. Срочные заявки попадают только в `Срочные`. Для общей таблицы `VoiceBot`/`Collection` сохраняется префикс направления.

## Схема Рабочей Таблицы

Для недельных и интеграционных вкладок используется единая схема:

1. `ID заявки`
2. `ID пачки`
3. `Тип заявки`
4. `Дата заявки`
5. `Направление`
6. `Тип ответа`
7. `Срочная`
8. `Автор заявки`
9. `Telegram ID`
10. `Статус`
11. `Редактор`
12. `Интент`
13. `Закрепленный сценарист`
14. `Причина изменений`
15. `Суть изменений`
16. `Исходная суть изменений`
17. `Исходный текст`
18. `Вопросы/комментарии редактора`
19. `Ответ сценариста`
20. `Итоговый ответ редактора`
21. `LLM статус`
22. `LLM оценка`
23. `Тип изменения`

Для `Раскатки` поле `Тип изменения` обязательно и принимает `ADD`, `EDIT` или `CHIPS`. В новых недельных вкладках заявка помещается в одноименную секцию. Старые недельные вкладки продолжают работать в плоском формате.

`Редактор` выбирается только в Google Sheets. Новая строка получает значение `Редактор не выбран` и dropdown со значениями из `APPLICATION_EDITORS`.

## Статусы

Одиночные заявки:

- `Новая`
- `В работе`
- `Нужны пояснения`
- `Итоговый ответ готов`
- `Принята`
- `Отклонена`
- `Отложена`

Строки внутри новых массовых заявок:

- `Новая`
- `Нужны пояснения`
- `Принято`

Новые массовые заявки целиком:

- `Новая пачка`
- `В работе`
- `Готова`

Для старых массовых заявок существующие dropdown и значения статусов автоматически не меняются.

В Google Sheets для статуса создается dropdown и цветовое оформление. Срочные строки получают отдельное визуальное выделение, но бизнес-правила для срочных ответов пока не зафиксированы.

## Одиночная Заявка

Flow одиночной заявки:

1. Выбор направления.
2. Выбор типа ответа для `ФЛ`, `SME`, `АИ`.
3. Интент.
4. Закрепленный сценарист.
5. Причина изменений.
6. Суть изменений.
7. Исходный текст.
8. Признак срочности.
9. Финальная проверка.
10. Отправка.

GigaChat используется только для одиночных заявок и только на поле `Суть изменений`. Если описание неполное, бот задает одно уточнение. Если GigaChat недоступен или ответ не удалось разобрать, заявка не блокируется: бот сохраняет исходный текст с LLM-пометкой для редактора.

## Массовые Заявки

Массовый режим не использует xlsx-файл в боте. Бот создает место в Google Sheets, а пользователь заполняет строки сразу в таблице.

Flow массовой заявки:

1. Пользователь выбирает `Массовая заявка`.
2. Выбирает направление.
3. Бот создает секцию массовой заявки в листе `Массовый ввод` выбранного направления.
4. Бот отправляет ссылку на место вставки и кнопку `Заявка заполнена`.
5. Пользователь заполняет строки в разрешенных колонках `A:G`.
6. Пользователь нажимает `Заявка заполнена`, после чего бот регистрирует заполненные строки, выдает `ID заявки` и ставит строковый статус `Новая`.

В шапке бот создает отдельный статус массовой заявки с dropdown `Новая пачка`, `В работе`, `Готова`. Строки новой массовой заявки используют dropdown `Новая`, `Нужны пояснения`, `Принято`.

GigaChat в массовом режиме не вызывается. Изменения статусов, комментариев и итоговых ответов отдельных строк не отправляются в Telegram.

## Дашборд

Дашборд является read-only представлением. Источник правды для статусов, комментариев и итоговых ответов - рабочие таблицы направлений.

В дашборде используется один лист `Заявки`: одиночные заявки отображаются отдельными строками, массовые заявки отображаются одной агрегированной строкой по `ID пачки`. Отдельные строки внутри массовой заявки в дашборд не добавляются.

Схема листа `Заявки`:

1. `ID заявки`
2. `ID пачки`
3. `Дата заявки`
4. `Направление`
5. `Тип заявки`
6. `Тип ответа`
7. `Срочная`
8. `Автор заявки`
9. `Статус`
10. `Редактор`
11. `Итоговый ответ есть`
12. `Ссылка на рабочую строку`

Бот создает или обновляет строку дашборда по `ID заявки` для одиночной заявки и по `ID пачки` для массовой заявки. Ручные изменения в дашборде не считаются источником данных.

## Уведомления

Polling читает рабочие таблицы направлений каждые `STATUS_POLLING_INTERVAL_SECONDS` секунд. Новая заявка появляется в дашборде сразу после отправки, а последующие изменения статуса, редактора и итогового ответа переносятся туда не чаще чем раз в `DASHBOARD_SYNC_INTERVAL_SECONDS` секунд. Заявки отслеживаются по `ID заявки`, поэтому сортировка и перемещение строк не ломают уведомления.

Для одиночных заявок автор получает уведомление при переходе в:

- `Нужны пояснения`
- `Итоговый ответ готов`
- `Принята`
- `Отклонена`
- `Отложена`

Для массовой заявки уведомление отправляется при переходе статуса всей пачки в `Готова`. Дополнительно бот присылает одно сгруппированное сообщение, если внутри пачки появились новые строки со статусом `Нужны пояснения`; в нем перечисляются заявки и комментарии редактора. Повторное уведомление по неизменившейся строке не отправляется. Переход в `В работе`, статус `Принято` и итоговые ответы строк уведомлений не создают.

Для одиночной заявки итоговый ответ отправляется только после перехода в статус `Итоговый ответ готов`. Комментарий редактора включается в уведомление только при статусе `Нужны пояснения`.

## Ручное Обновление Существующих Таблиц

Автоматическая миграция схемы не выполняется. Перед развертыванием версии с редакторами:

1. В каждой рабочей вкладке вставьте колонку `K` и назовите ее `Редактор`.
2. В дашборде вставьте колонку `J` и назовите ее `Редактор`.
3. В листах `Массовый ввод` вставьте колонку `J` во всем листе и укажите `Редактор` в каждой строке заголовков массовой заявки.
4. При необходимости добавьте dropdown и заполните старые строки значением `Редактор не выбран`.

Новые записи в старую схему блокируются. Polling продолжает читать старые рабочие строки, поэтому текущие уведомления не теряются.

## Форматирование Исходного Текста

Для одиночных заявок бот сохраняет из Telegram только:

- жирный текст;
- зачеркнутый текст.

Это форматирование переносится в Google Sheets как rich text в колонку `Исходный текст`. В массовом режиме rich text не переносится, потому что строки вставляются пользователем вручную в Google Sheets.

## Запуск В Docker

```bash
docker compose build
docker compose up bot
```

SQLite-база хранится в Docker volume, поэтому черновики, дефолты и tracking-данные переживают перезапуск контейнера.

После изменения временной зоны или дедлайнов пересоздайте контейнер без удаления volume:

```bash
docker compose up -d --build --force-recreate bot
```

## Ручная Проверка

1. Создайте Google-таблицы направлений и дашборда.
2. Дайте service account права редактора во всех таблицах.
3. Заполните `.env` новыми `GOOGLE_*_SPREADSHEET_ID`.
4. Запустите `docker compose up bot`.
5. Создайте одиночную заявку в Telegram и проверьте появление строки в недельной или интеграционной вкладке.
6. Измените статус или итоговый ответ в рабочей таблице и дождитесь уведомления в Telegram.
7. Создайте массовую заявку, вставьте строки в подготовленный блок, нажмите `Заявка заполнена` и проверьте регистрацию строк.

## Открытые Вопросы

- Срочные ответы пока имеют только булевый признак и визуальное выделение; маршрутизация срочных заявок требует отдельного решения.
- Для раскатки и каждой заполненной строки массовой заявки обязателен `Тип изменения`: `ADD`, `EDIT` или `CHIPS`.
- Массовая заявка сейчас работает только в листе `Массовый ввод`; строки не дублируются в недельные, срочные или интеграционные вкладки.
- Автоматическая миграция старых Google Sheets `Высокий`, `Низкий`, `Массовые` в новую модель не выполняется.
- Ответ сценариста через Telegram пока не реализован; пользователь получает ссылку на рабочую строку.
